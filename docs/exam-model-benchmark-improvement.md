# 模試読み取りの追加検証：モデル選択と採用判断

**最新の記録:** [検証・復旧の本体実装、Flash／Pro比較と採用判断](exam-reading-reliability.md)。以下はv2実験時点の記録であり、実装前の判断を保持している。現在の累計費用・検証結果は最新記録を参照。

**模試読取の第一候補はGemini 2.5 Flashを維持する。Flash-Liteへの統一は見送る。モデルを増やす比較はここで区切る。**

判断の範囲：Flashより上位の候補は今回比較していないため、「Flashが最適」「上位モデルは不要」と実証したわけではない。比較を区切るのは作業の優先順位の判断。まずモデルに依存しない検証・復旧の不具合を直し、その後も表区分の誤認や確認負担が残る場合は、上位候補1つとの少数比較で追加費用に見合う改善があるかを判断する。表区分の誤認は上位モデルで減る可能性があるが、数値範囲のチェックだけでは検出できず、元の表見出しとの対応や不確かな結果を自動反映しない設計が必要になる。

読み取りと提案生成を分離した実験では、Flashの回答が返った初回8入力で、採点対象の数値がすべて一致した。ただし1入力のタイムアウト、再試行時の分類違い、対象外の偏差値の混入、検証処理の過剰な除外も発見した。**実験版をそのまま自動反映へ組み込む判断はしない。** 本体のモデル設定・模試解析ジョブ・環境変数・DBは変更していない。

実験用の抽出・検算コード、採点コードと試験を追加した。前回の回答と採点は保存したまま、今回分を別ディレクトリに記録している。

## 今回確かめたこと

前回は「画像の転記」と「目標・苦手・学習時間の提案」を1回で求めていた。今回はAIに表の抽出だけを依頼し、各行の種類、科目、設問、本人得点、満点、全国偏差値、全国平均**点**を分けた。不明な値はnullとする。得点率・平均との差・初期の復習候補はコードで計算する試作にした。

- 同じ正規化済み9入力、本人承認済み正解表、同じ450項目／モデルを使用。模試2回分・3ページの撮影条件違いであり、独立した9回の模試ではない。
- Flash-Lite→Flashの順にOrcaReplayで比較。画像を保持し、比較forkではモデル名だけを変える。前回のGPT-4o miniは再比較しない。
- 実際のOrcaReplayプロキシと外部通信しない上流スタブでも、今回の要求がモデル名以外すべて一致することを確認した。
- 画像の解像度・JPEG品質は前回と同じ。入力画像を拡大・切り出ししていない。
- 出力上限は6,000→10,000トークンに変更。プロンプト・スキーマも変更したため、改善を一つの変更だけの効果とは断定しない。
- 1試行60秒、初回比較ではフォールバック・JSON修復なし。全9条件取得後、通信タイムアウトの1件だけ同じ要求で1回再実行した。内容が間違った回答を正解になるまで繰り返してはいない。
- 本体の個別学習計画生成はどちらのベンチマークにも含まない。今回の初期プロフィール案はルールによる提案で、教育効果や学習時間の妥当性の実証ではない。

## 初回比較：失敗を含めた同じ分母

必要項目を、科目・設問・列の意味まで正しく取り出せた割合。文字認識率ではない。費用はOrcaRouterが返した額で、費用不明のタイムアウトをゼロ円とみなさない。

| 前回Flash | 399/450（88.7%） | 7/9 | 8/9 | 20.53秒 | $0.097298 |

## 再試行は別の補助結果として扱う

FlashのA_scanを同一要求で1回再実行すると、16.10秒・$0.010768で応答した。対象57項目のうち55項目を取得。残る2項目の数字は出ているが、換算合計を実得点側の集計行に分類したため、換算得点として取得できたとは数えない。

9入力で初回失敗後の1回再試行を含める補助集計は、**448/450（99.6%）、全対象一致8/9、確認費用$0.113014＋不明1件**。API呼び出しは10回。A_scanの2回分のAPI待ち時間は合計76.11秒。この値は実行の間の待機時間を含む実測ユーザー待ち時間ではない。

この99.6%は本体の成功率でも、未知の模試での精度保証でもない。前回にも同じ復旧方式を適用した比較ではないため、「88.7%から99.6%に向上」とだけ書かない。

さらに、再試行結果では対象外と指定した私大評価用偏差値5行を、通常の科目の全国偏差値欄に入れていた。これは450項目の主指標だけでは見えない追加出力の問題。**99.6%でも、そのまま学習計画へ流すのは不適切**と判断する根拠になる。

## 検算コードから分かったこと

実験コードは、満点超過、不明確な行、平均点と満点の不整合、禁止した列への値の混入、重複した行の競合などを除外する。得点率は `本人得点 / 配点`、平均との差は `本人得点 − 全国平均点` とし、点と％を混ぜない。平均を上回る単元を低い素点だけで苦手と断定しない。

一方で、今回の検証ルールには過剰除外がある。B_scan・Flashは同じ偏差値を表とグラフから重複して返し、一方には得点がなかった。値自体は一致しているが、行全体の違いで競合と判定し、正しい12項目も取り除いてしまった。

初回の「抽出時に正しい項目」と「実験の検証後も残る正しい項目」はFlashが393→381、Liteが363→196。再試行込みFlashでも448→403。残った採点対象セルには誤った数値はなかったが、前述の対象外の行が残る問題は別にある。検算は読み間違いの完全検出器ではない。

このため、実験コードは `scripts/benchmarks/structured-extraction.ts` に隔離し、本体から呼び出していない。採用前に必要な作業は、次のように絞れた。

1. 同一科目の重複はセル単位で照合し、同じ値・欠損の補完と、本当の数値矛盾を区別する。
2. 実得点／換算／私大評価／全国・校内等の表区分を根拠と一緒に扱い、対象外の表を計画へ混ぜない。
3. 対話と模試解析の時間制限を分け、解析ではチェックポイントを保存した有限回の再試行を行う。失敗を低精度モデルのもっともらしい結果で埋めない。
4. 修正後に今回未使用の模試で、誤った自動反映と人による確認が必要な割合を評価する。同じ3ページへの改善だけで一般化しない。

今後時間を使う対象は、候補モデルを増やすことより、この具体的な取り込み処理と確認画面の整備。今のサービスでは模試用の `vision` はFlashが既定で、ローカル環境にも上書き指定はなかった。ただし既存の代替先にはGPT-4o miniが残っている。今回それを検証済みの安全な代替と説明しない。会話・音声・一般の授業資料のモデル選択は今回の試験対象外。

## 費用と互換性エラーも記録する

| 区分 | API呼び出し数 | 確認できた費用 | 費用不明 |
| --- | ---: | ---: | ---: |
| 前回まで | 40 | $0.201082 | 1件 |
| 今回追加 | 21 | $0.122786 | 3件 |
| 累計 | 61 | **$0.323868** | **4件** |

今回21回の内訳は、最終形式の主比較18回、タイムアウト後の再試行1回、準備段階のHTTP 400が2回。400は最終形式の精度集計には入れず、費用管理・失敗記録からは除いていない。

最初は複雑なスキーマが拒否され、簡略化後はnullable型の配列表記が互換経路で拒否された。送信スキーマを簡潔にし、nullableをanyOf形式にして通過した。細かな範囲・長さ制約はローカルで検証する。Gemini公式も構造化出力がJSON Schemaの一部のみを扱い、構造の保証と意味の正しさは別と説明している（[公式ドキュメント](https://ai.google.dev/gemini-api/docs/structured-output)）。

費用不明4件に各$0.25を留保した**予算管理額は$1.323868／承認上限$2**。これは実請求額ではない。400が無課金だった、タイムアウトが無料だった、と推定して留保を解除していない。最終請求額はOrcaRouter側との照合が必要。実験用アカウントだけを使用し、チームメイトの本体キーを使った追加API呼び出しはない。

## この検証から言えること

実際の模試を9つの入力条件でOrcaReplay比較し、さらに読み取りと提案生成を分離して再評価しました。Flashは今回の初回8入力で必要項目がすべて一致しましたが、1件のタイムアウトがありました。Liteは安価でも得点の欠落や偏差値の混同が残ったため、模試の第一候補はFlashとしています。再試行を含めると採点対象の99.6%を取得しましたが、対象外の偏差値が混ざる問題も発見し、実験版の自動反映は見送っています。モデルの価格だけでなく、失敗・誤反映・確認作業まで含めて採用を判断している。

- **コストパフォーマンス:** 累計の確認費用約$0.324で、最安モデルへの統一を見送る具体的な根拠を得た。改善しても費用や待ち時間が増える点も示す。
- **信頼性・堅牢性:** JSON成功、抽出正確性、検算後の利用可能性、復旧を別々に測る。未検証の本番復旧を実装済みと言わない。
- **自律性:** AIが読み取り、コードが検算し、先生が疑義と計画を確認する役割分担につなげる。実験部分と現在の実装を区別する。
- **セキュリティ:** 資料内の指示を命令として扱わないプロンプトとガードを継承。今回攻撃入り画像での耐性試験はしていない。
- **位置づけ:** 説明対話・復習・学習計画へ、信頼できる初期情報を渡すための入口にあたる。

示すべきは初回比較表と「何を採用し、何を見送ったか」で、再試行後の99.6%だけを大きく扱わない。

## 保存先と再現方法

原画像・生の回答・項目別採点はGit対象外の `benchmark-data/` に保存。公開用の記事やリポジトリに成績表を添付しない。

- `exams/runs-structured-v2/protocol.json`: 最終実験条件と元ソースのハッシュ
- `exams/runs-structured-v2/extraction-source.ts`: 実行時の元ソース。実験後、コードは上記scripts配下へ移動し、アプリ依存を明確に分離した
- `exams/requests-structured-v2/`: 実際の要求。元画像は既存normalizedと同じ
- `exams/runs-structured-v2/responses/`: 初回回答、タイムアウト、準備段階400
- `exams/runs-structured-v2/responses-retry/`: 1回だけの復旧試行
- `exams/runs-structured-v2/{scores.json,field-scores.csv,aggregate.json}`: 初回採点
- 同ディレクトリの `recovery-*`: 復旧を含む補助集計。初回を上書きしない
- `exams/work-structured-v2/.orca/runs/`: OrcaReplayの記録・比較fork
- `exams/runs/ledger.json`: 前回から共通の費用台帳

採点は科目名の表記揺れを正規化し、設問番号・単元名を照合する。同じ値の重複は1値、競合する複数の値は不明確と数える。AI回答と対応規則をエージェントが点検したもので、人間による独立した二重採点ではない。数値の正解表・450項目の分母は変更していない。

以下は保存結果の再集計のみで、API費用は発生しない。

```sh
node --import tsx scripts/benchmarks/score-exam-structured.mts
node --import tsx scripts/benchmarks/score-exam-structured.mts --recovery
```

追加の有料実験はこの記録で終了。再実行時に古い試行を上書きしたり、良い回答だけを選び直したりしない。

検証コードの単体試験7件と変更ファイルのESLintは通過。リポジトリ全体の型検査は、ローカルに `playwright-core` と `react-day-picker` が未導入であることによる既存ファイルのエラーで完了できなかった。今回アプリのビルド・本番動作を検証済みとはしていない。
