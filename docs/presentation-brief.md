## 記事の骨子

見出し案：**先生は授業に集中。AIが、一人ひとりの復習を設計する「トイノワ」**

1. **課題。** 授業後に先生が抱える、個別の宿題設計・理解度確認・次回準備。人数や時間の数字は実測がある場合にだけ入れる。
2. **体験。** 同じ一人の生徒を追う短いデモと、先生・AI・生徒の役割図。クラスなしの個別指導でも使えることを示す。
3. **自律化した仕事。** 授業記録を渡してからAIがどの根拠で案を作り、どこで先生の判断へ戻すか。AIが判断する部分とコードの固定処理を区別する。
4. **5基準の根拠。** [根拠集の表](evidence.md#5つの評価項目に対する説明)から、各基準の主張・画面・試験を短く示す。
5. **実測から変えた設計。** 模試の読み取りを分離・検証し、上位モデルとの比較も経てFlashを維持した例。単価以外に待ち時間・失敗・確認負担を測ったことを示す。
6. **運用の限界と次の検証。** 未知の帳票・攻撃画像・学習効果・作業時間は未検証部分を具体化する。
7. **再現方法。** 公開コード、起動方法、モデル設定、比較の分母と条件、公開可能な集計JSON。原資料やキーは公開しない。

## 4分のピッチ案

| 時間 | 内容 | 示すもの |
| --- | --- | --- |
| 0:00–0:30 | 先生の授業後の負担と対象ユーザー | 一文の課題、先生・AI・生徒の役割図 |
| 0:30–1:20 | 授業記録→個別案→先生の配信 | 対象生徒、案の根拠、承認画面 |
| 1:20–2:00 | 生徒が説明→AIが問い返す | 実際の対話。初回自己紹介だけでデモを終えない |
| 2:00–2:35 | 根拠付き分析→次回の計画 | 根拠発言、先生の修正、前の計画とのつながり |
| 2:35–3:25 | 費用対効果・信頼性 | 小さなFlash/Pro比較表、確認待ちの原資料照合 |
| 3:25–4:00 | セキュリティと適切な人の判断、結論 | 防御の仕組みと検証範囲。学習効果・削減率を捏造しない |

読み取りに時間がかかる場面は、事前に準備した結果か待機を省いた録画で示す。録画をライブと説明しない。先生の操作・AIの処理・生徒の学習を混同しない。

- 初回450項目と追加の3スキャン150項目を合算・同列比較して改善率を作らない。
- 66回の呼び出しを66種類の模試と表現しない。

- 自動テストの成功件数をAIの正答率・攻撃防御率に置き換えない。
- キャッシュを使いやすい配置と入力数の記録は実装済みだが、実測の削減率は未確認。
- 旧名の画面素材は最新版へ撮り直す。実在生徒・キー・ログイン情報は載せない。

個々のAIとの会話は調査の手がかりとして扱い、記事の確定した主張はコード・保存された結果・条件に結び付ける。これは誰が記事を書く場合も共通する。
