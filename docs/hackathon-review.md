# 実装後のテーマ・評価基準との対応

テーマは「業務を自律化するAIエージェント」。StudyPilotの対象業務は、塾の先生の宿題準備、理解度確認、次回指導の準備。
利用者と合意した境界は、AIが計画・宿題候補・振り返りを作成し、先生が対象生徒と期限を決めて配信すること。無限にお題を自動配信する設計にはしない。

| 基準 | 実装で示せること | 勝つために残る検証・弱点 |
|---|---|---|
| セキュリティ | JWT/RLSによる学校・担当生徒の範囲制限。詳細評価と計画表は生徒へ直接公開しない。教材・模試を命令として扱わない読み取り、入力検査・個人情報マスク・出力検査。公開は先生の承認。 | ルール検出だけでは未知の攻撃を網羅できない。画像内の間接インジェクションを含む攻撃セット、OrcaRouter側のGuardrails/Firewall設定の実確認が必要。 |
| コストパフォーマンス | 難易度別モデル、評価は対話完了時に1回。利用者×モデル別の実行・トークン・費用を可視化。autoとGPT-5 nanoの実測比較を保存。 | 比較は人工例2件のみ。各科目・誤答・短い相づち・複数ターンを含む教師評価付きデータで品質と費用を測る。タイムアウトした上流の課金は応答で取得できない場合がある。 |
| 信頼性・堅牢性 | AI応答のスキーマ検証、時間上限、別モデルへの切替、失敗時の確認待ち。ジョブの再試行・リース・失敗退避。お題作成と承認はDBトランザクション、再実行時の重複防止。 | 実モデルautoで長い評価の遅延を観測して時間上限を追加。本番のworker到達性・定期再試行・障害注入のデモが必要。既存0012のマイグレーション履歴不一致は別途整合確認。 |
| 自律性 | 入力情報から学習計画・宿題候補を選び、説明に応じた質問を返し、会話全体を評価して次回候補を更新。先生は公開・期限・評価の修正に介在。 | 現在は限定した処理の流れであり、任意の外部ツールをAIが自ら選ぶ実装ではない。ツール登録基盤だけを「実装済み自律選択」と説明しない。AIが選んだ難易度・問い・候補の根拠をデモで示す。 |
| アイデア・独創性 | 「生徒がAIに教える」対話と、模試・授業教材・会話根拠を接続し、次の宿題判断へつなぐ。生徒には励まし、先生には詳細分析を分ける。 | 過去の受賞作にも問いを重視した学習支援がある。独創性は対話形式だけでは弱い。先生の実際の準備・確認時間削減と、根拠から介入できる体験を見せる。 |

## デモで見せる流れ（4分を想定）

1. 先生が宿題の準備・個別確認に時間を使っている課題を示す。
2. 模試画像から弱点を読み取り、根拠のある学習計画と宿題候補が生成される。先生が期限を設定して配信。
3. 生徒が説明し、AIが確認質問を選ぶ。途中は評価を出さず、完了後に短い励まし。
4. 先生の画面で誤概念の根拠発言と次回の候補を示す。自動配信せず人が判断する箇所を説明。
5. モデル別費用、タイムアウト時の切替、教材インジェクションの遮断を短く示す。

## モデルの実測

`feedback-model-evaluation.json`に2026-09-21 JSTの比較を保存。
同じ人工例2件で、GPT-5 nanoは合計$0.001250、autoは$0.000514（どちらも2件の検査を通過）。autoの解決先は2件ともGLM-5.3 Flash。
この2件に限る費用差は約59%だが、全体のコスト削減率・一般的な教育品質として主張しない。
実際のアプリの長い評価ではautoの待ちが長くなるケースも観測した。短いスモークだけで最適モデルを確定せず、評価時間を制限して代替へ切り替える。

テーマ・各10点の5基準・提出条件・OrcaRouter賞5万円の訂正は`hackathon.md`を継続参照する。

## 今回の動作確認

- 自動テスト66件、ESLint、TypeScript、本番ビルド（webpack）が成功。
- 接続先DBで、候補の重複防止・承認後の配信・生徒から計画表と詳細評価を参照できないことを確認。検証トランザクションはロールバック。
- 実際のOrcaRouterを使い、管理者による登録→模試画像の読み取り→先生の教材からのお題提案・配信→生徒の対話→最終評価→次回計画と未配信の宿題候補→先生の承認→利用者別のモデル集計まで通過。一時学校とユーザーは削除済み。
- 長い評価でautoからGemini Flashへ切り替わり、約26秒で実応答による評価を取得した実行を確認。すべてのモデルが停止する障害試験とは区別する。
- ChromeでPDFのページ画像変換と読み取り結果の入力反映、登録画面、先生のお題画面、モバイル幅を確認。PDF変換のブラウザテストは抽出API応答を固定し、画像OCR自体は上記の実APIテストで別途検証した。
