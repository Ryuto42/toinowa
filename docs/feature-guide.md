# 機能仕様とモデル設定

画面の操作手順は [使い方ガイド](user-guide.md) を参照してください。ここでは実装側の仕様・モデル設定・検証方法をまとめます。設計判断に至った経緯と実測は [開発記事](qiita-article.md) にあります。

## 一周の流れ

1. 管理者がユーザーを登録する。生徒は氏名・学年が必須で、クラス・目標・模試・苦手範囲・学習時間は任意。個別指導では担当の先生と生徒を直接結び付ける。模試はPDF・写真を選んだ時点で分析を始め、登録後でも反映できる。
2. 先生が「授業と宿題」で、対象クラス・期限・授業メモまたは資料を渡す。クラスの在籍生徒それぞれについて、過去の説明・評価・模試情報を参考にした学習計画と最初の課題案をバックグラウンドで準備する。
3. 「先生の確認待ち」で、お題・理由・時間の目安・注意点を確認する。必要なら編集し、まとめて承認・配信する。生徒には承認済みの課題だけが見える。
4. 特定のテーマや直接のお題指定は画面下部の補助機能として残してある。通常は先生が問題文や難易度を設計する必要はない。
5. 生徒は指定されたお題をAIに説明する。対話中に点数・評価は返さず、観点を変える問いかけと説明のし直しを促すだけにする。
6. 完了後に分析し、生徒には良かった点と次の一歩の簡易版を、先生には根拠付きの詳細を表示する。説明の改善が観測できた場合は具体的に伝える。
7. 評価と先生の修正から、今回の授業範囲と前の計画を踏まえて次回の計画・課題案を更新する。生徒詳細に変更理由と根拠の評価へのリンクを出す。次の課題は自動配信しない。
8. 管理者は「AI利用状況」で利用者・機能・モデル・費用を確認する。

## 資料と模試の扱い

- PDFは8ページ・元ファイル15MBまで。ブラウザでページ画像に変換するのでスキャンPDFにも対応する。送信時の画像合計は3.5MBまで。授業資料の画像原本はDBに保存しない。
- 模試の画像は非公開テーブルへ一時保存し、自動反映の完了時・失敗時に削除する。確認待ちになった場合だけ承認まで保持し、その後削除する。
- PDF・画像内の文字は信頼しない。読み取り専用の画像対応モデルで抽出し、入出力検査を通したうえで人が確認する。読み取りモデルにツールも公開権限も与えない。
- 読み取れない値は推測させない。空欄と確認事項として返し、人が直す。写真内の個人情報は送信前に除く。
- 疑義のある結果は確認画面で元資料と照合・修正して承認するまで反映しない。承認者・時刻・元の抽出・修正前の提案を残す（`0053_exam_review.sql`）。
- 「模試の分析状況」で処理状況を確認できる。失敗したときは再アップロードか手入力で進められる。
- 資料の読み取りは一度だけ行い、抽出したテキストを生徒別の計画生成で共用する。保存済みの計画から再開する場合はモデルを呼び直さない。

## モデルの段

| 用途 | 環境変数 | 既定 |
| --- | --- | --- |
| 難易度1〜2の対話 | `AI_ECONOMY_MODEL` | `google/gemini-2.5-flash-lite` |
| 難易度3の対話 | `AI_STANDARD_MODEL` | `google/gemini-2.5-flash` |
| 難易度4〜5と最終評価 | `AI_ADVANCED_MODEL` | `orcarouter/toinowa-advanced` |
| 教材の画像読み取り | `AI_VISION_MODEL` | `google/gemini-2.5-flash` |
| 模試の読み取り | `AI_EXAM_MODEL` | `google/gemini-2.5-flash` |
| 音声の書き起こし | `AI_AUDIO_MODEL` ほか2段 | Google系のみ |

- `orcarouter/toinowa-advanced` は OrcaRouter コンソールで作ったアダプティブルーター。候補を `google/gemini-2.5-flash` `google/gemini-2.5-flash-lite` `openai/gpt-4o-mini` `openai/gpt-4o` の4件に限定している。組み込みの `orcarouter/auto` は候補が無制限で、難問では `anthropic/claude-opus-5` などへ上がるため使わない。
- 一般の用途別呼び出しは1回15秒・全体45秒を上限に別モデルへ切り替える。
- 模試専用の `exam` は1回60秒・全体65秒で、**別モデルへは切り替えない**。ページ単位の保存済み進捗から再開し、通信失敗と不正なJSONは同じページを1回まで再試行する。未検証の別モデルで模試を補わない。予算・安全性による遮断は再試行しない。
- 画像読み取りの代替も画像対応モデルに限定する。
- 修復で取得できた使用量は合算する。管理画面は最終応答モデル別の集計で、途中の試行は実行詳細から見る。タイムアウト後に上流で発生した費用は応答を受け取れないため集計できない場合がある。

## 音声入力

- `AI_AUDIO_MODEL` → `AI_AUDIO_STANDARD_MODEL` → `AI_AUDIO_ADVANCED_MODEL` の順に降りる。音声を受けられるのはGoogle系だけなので他社へは分散できない。全滅時はテキスト入力へ縮退する。
- 音声はゲートウェイのガードレールで検査できない（バイナリのため対象外）。書き起こし（raw / refined の両方）を通常のテキストと同じ `preCheck` に通してから本文として扱う。音声そのものは保存しない。
- 書き起こしは音声認識の誤りだけを直した文を返す。説明を補う・要約する・言い換えるのは禁止。認識前の文字列も返させると出力トークンが倍になり体感で約1秒遅くなるため、出力は1本にしている。
- 区切りごとに「直前までの書き起こし」と「直前のAIの発言」を文脈として渡す。渡さないと同音異義語を外す（実測：「直線の」→「直前の」、「切片」→「せっぺん」）。
- 区切りは直列に投げず並行して投げ、画面に出す順番だけ揃える。直列だと前の応答待ちがそのまま積み上がる。
- OrcaRouter は音声を含む応答に `usage.cost_usd` を返さない（実測）。返らない場合はカタログ（`/v1/models`）の単価から推定して計上する。音声は文字より単価が高いため、予算のガードが安全側に倒れるよう3.5倍で見積もる。確定額は請求で確認する。
- `agent_runs.audio_input_tokens` に音声ぶんのトークンを残す。Geminiは毎秒32トークンで数えるため、発話時間の算出に使える。

## アカウントと認証

- 新規生徒はメールアドレス不要。ログインIDは所属ごとに `student1`、`student2`… とDBで自動採番する。登録画面でのID入力は不要。既存番号・同時登録・削除後の非再利用に対応し、既存ユーザーのIDは変えない。
- 初期パスワードは全ロールでサーバーが自動生成する。登録直後のポップアップで所属コード・ログインIDまたはメールアドレス・初期パスワードをコピーできる。画面を閉じると再表示できず、ログにも残さない。
- 生徒は「所属コード＋ログインID＋初期パスワード」でログインし、12文字以上の別のパスワードへ変更する。変更前は学習画面・API・DBの所属データへのアクセスを制限する。既存ユーザーに初回変更を一括要求はしない。
- 管理者はユーザー編集画面の「初期パスワードを再発行」から所属内の全ロールをリセットできる。再発行後は本人による変更を必須にする。古いセッション・更新トークンとJWT世代も失効し、同時の変更操作は排他制御する。
- ログイン画面の「所属コードをこのブラウザに保存する」を選ぶと、所属コードだけを localStorage へ保存する。チェックを外すと削除する。ID・パスワードはこの機能では保存しない。
- DBの既存名 `school_codes` と旧APIパラメータ `schoolCode` は互換性のため残し、画面と新しいAPI入力は「所属コード」／`organizationCode` とする。

## 登録情報の編集

管理者の「ユーザー管理」→対象ユーザーの「編集」で変更する。氏名・利用状態に加え、生徒はログインID・学年・利用目的・模試結果・苦手範囲・1日の学習時間を更新できる。模試結果はPDF・画像からの読み取りにも対応する。

基本情報と学習プロフィールはまとめて保存し、エラー時に一部だけ変わることがないようにしている。更新した情報は次回の学習計画と個別のお題生成に使う。保存操作だけでは宿題の再生成も自動配信も行わない。

登録時の必須項目は氏名とロール。生徒は学年、先生・管理者はメールアドレスも要る。担当の先生とクラスは任意で、後から設定できる。利用目的・目標、苦手範囲、模試結果、1日の学習時間も任意で、未設定の学習時間はDBでも null とし、計画生成の時間上限だけ内部の仮値として30分を使う。

初期の目標と時間は、検査した模試結果からコードで作る変更可能な提案であり、本人の希望や最適時間の断定ではない。

## 個別指導と利用終了

クラスは任意。生徒の登録・編集で担当の先生を指定すると、「授業と宿題」で生徒を直接選べる。集合授業は従来どおりクラス指定を使う。個別指導の学習領域は内部で自動作成し、既存RLSの担当制限を引き継ぐ。既存生徒にも領域を用意するが、新しい担当権限は自動付与しない。

管理者は生徒の編集画面とクラス管理からアーカイブ・復元できる。完全削除はアーカイブ後に影響件数と名前入力で確認し、DBトランザクションで実行する。生徒削除では認証アカウントも消し、クラス削除では在籍者のアカウントや別の学習領域は残す。実行中のジョブがある間は削除を拒否し、アーカイブ後の新規書き込み・ジョブ開始にもガードを置く。監査ログと所属の費用集計は保持する。

計画詳細と授業記録は生徒に非公開。新規の計画は先生の担当クラスでも制限し、別クラスで同じ生徒を担当しているだけでは読めない。

## 対話の取り消し

自己紹介・通常の課題のどちらでも、開き直したときに保存済みの最後の1往復から取り消しボタンを復元する。終了済みと返信待ちには表示しない。

`0054_persist_conversation_undo.sql` で、取り消した直後に残る最後の生徒メッセージIDを記録している。再読み込みや別タブからさらに古い往復を取り消す操作はDB側でも拒否する。新しい送信は別のIDになるので、あらためて取り消せる。

## 検証

```bash
npm ci
# .env.example を参考に .env.local を用意
npm run db:push
npm run db:types
npm run dev
```

```bash
npm test            # ゴールデンテストを含む全体（46ファイル・334件）
npm run lint
npx next typegen && npx tsc --noEmit
npm run build
```

| コマンド | 内容 |
| --- | --- |
| `npm run test:db` | 接続先にDDLと検証データを一時作成し、必ずロールバックする。既存の同一学校の管理者と生徒が必要 |
| `npm run test:smoke` | 起動中のアプリに一時学校・ユーザーを作り、OrcaRouterを実際に呼ぶ。終了時に作成データを削除する。既存ユーザーのデータは触らない |
| `SMOKE_AUTH_ONLY=1 npm run test:smoke` | 実認証の一連の処理をAI呼び出しなしで確認する |
| `npm run check:injection` | テキスト経路のプロンプトインジェクション検査 |
| `npm run check:injection:image` | 画像経路のプロンプトインジェクション検査（`--live` で実課金） |

教材の読み取りと計画生成には外部AIへの接続が必要。ローカルではAPIが `APP_BASE_URL` のworkerを起動する。本番の定期再試行には `private.app_config` のworker URLと共有シークレットが要る。

模試読み取りの実測結果と限界は [模試解析の採用判断・実装記録](exam-reading-reliability.md) を参照。
