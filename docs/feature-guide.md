# 宿題の準備と振り返り

画面を使う方は [使い方ガイド](user-guide.md) を参照してください。以下は実装・検証を含む補足です。

## 操作

1. 管理者がユーザーを登録。生徒の氏名・学年は必須、クラス・目標・模試・苦手範囲・学習時間は任意。個別指導では担当の先生と生徒を直接結び付ける。模試はPDFや写真の選択時に自動分析し、登録後も反映できる。
2. 先生の「授業と宿題」で、対象クラス・期限・授業メモまたは資料を渡す。クラスの生徒全員について、同じクラスの過去の説明・評価・模試情報を参考に、個別の学習計画と最初の課題案をバックグラウンドで準備する。
3. 「先生の確認待ち」で、お題・理由・時間の目安・注意点を確認。必要時に編集し、確認した課題をまとめて承認・配信する。生徒には承認済みの課題だけを表示する。
4. 特定のテーマや直接のお題指定は、画面下部の補助機能として残す。通常は先生が問題文や難易度を設計する必要はない。
5. 生徒は指定されたお題についてAIに説明する。対話中に点数・評価は返さず、観点を変える問いかけや説明し直しを促す。
6. 完了後に分析し、生徒には良かった点と次の一歩の簡易版、先生には根拠付きの詳細を表示。説明の改善が観測できる場合は具体的に伝えるようにする。
7. 評価・先生の修正から、今回の授業範囲と前の計画を踏まえて次回の計画・課題案を更新。「生徒」詳細に変更理由と根拠となった評価へのリンクを表示。次の課題は自動配信しない。
8. 管理者の「AI利用状況」で利用者・機能・モデル・費用を確認する。

## ファイル・モデル

- PDFは8ページ・元ファイル15MBまで。ブラウザでページ画像に変換するため、スキャンPDFにも対応。送信時の画像合計は3.5MBまで。授業資料の画像原本はDBに保存しない。模試の画像は非公開テーブルに一時保存し、自動反映の完了・失敗時に削除する。確認待ちの場合のみ承認まで保持し、その後削除する。
- PDF/画像内の文字は信頼しない。読み取り専用の画像対応モデルで抽出し、入出力検査後に人が確認。読み取りモデルにツール・公開権限は与えない。
- 模試結果の不足・読み取れない文字は推測させず、人が修正する。写真内の個人情報は送信前に除く。
- Lv.1〜2: `AI_ECONOMY_MODEL`、Lv.3: `AI_STANDARD_MODEL`、Lv.4〜5と最終評価: `AI_ADVANCED_MODEL`。
- 現在の評価既定は`orcarouter/toinowa-advanced`。OrcaRouter コンソールで作成したアダプティブルーターで、候補を `google/gemini-2.5-flash` `google/gemini-2.5-flash-lite` `openai/gpt-4o-mini` `openai/gpt-4o` の4件に限定している。組み込みの `orcarouter/auto` は候補が無制限で、難問では `anthropic/claude-opus-5` などへ上がるため使わない。
- 一般の用途別呼び出しは1回15秒、全体45秒を上限に別モデルへ切り替える。模試専用の `exam` は1回60秒・呼び出し全体65秒で、別モデルには切り替えずページ単位の再試行を行う。修復で取得できた使用量は合算する。管理画面は最終応答モデル別の集計であり、途中の試行は実行詳細で確認する。タイムアウト後に上流で発生した費用は応答を受け取れず、集計できない場合がある。
- 画像読み取り: `AI_VISION_MODEL`。代替も画像対応のモデルに限定する。
- 音声入力: `AI_AUDIO_MODEL` → `AI_AUDIO_STANDARD_MODEL` → `AI_AUDIO_ADVANCED_MODEL` の順に降りる。音声を受けられるのは Google 系だけなので他社へは分散できない。全滅時はテキスト入力へ縮退する。
- 音声はゲートウェイのガードレールで検査できない（バイナリのため対象外）。書き起こし（raw / refined の両方）を通常のテキストと同じ `preCheck` に通してから本文として扱う。音声そのものは保存しない。
- 書き起こしは音声認識の誤りだけを直した文を返す。説明を補う・要約する・言い換えるのは禁止。認識前の文字列も返させると出力トークンが倍になり体感で約1秒遅くなるため、出力は1本にしている。
- 区切りごとに「直前までの書き起こし」と「直前のAIの発言」を文脈として渡す。渡さないと同音異義語を外す（実測: 「直線の」→「直前の」、「切片」→「せっぺん」）。
- 区切りは直列に投げず並行して投げ、画面に出す順番だけ揃える。直列だと前の応答待ちがそのまま積み上がる。
- OrcaRouter は音声を含む応答に `usage.cost_usd` を返さない（実測）。返らない場合はカタログ（/v1/models）の単価から推定して計上する。音声は文字より単価が高いため、予算のガードが安全側に倒れるよう 3.5 倍で見積もる。確定額は請求で確認する。
- `agent_runs.audio_input_tokens` に音声ぶんのトークンを残す。Gemini は毎秒32トークンで数えるため、発話時間の算出に使える。
- 比較記録: `docs/data/feedback-model-evaluation.json`。人工的な2例では両候補が合格したが、一般的な採点精度を示す評価セットではない。

## 検証・運用

```bash
npm ci
# .env.exampleを参考に.env.localを用意
npm run db:push
npm run db:types
npm run dev

npm test
npm run lint
npx next typegen && npx tsc --noEmit
npm run build
```

`npm run test:db`は接続先にDDLと検証データを一時作成し、必ずロールバックする。既存の同一学校の管理者と生徒が必要。
`npm run test:smoke`は起動中のアプリに対して一時学校・ユーザーを作り、OrcaRouterを実際に呼ぶ。終了時に作成したデータを削除する。既存ユーザーのデータは操作しない。
`npm run benchmark:feedback`は人工的な2例×2モデルの比較。直接呼び出すためアプリの利用台帳には含まれない。

教材の読み取りと計画生成には外部AIへの接続が必要。ローカルではAPIが`APP_BASE_URL`のworkerを起動する。本番の定期再試行には`private.app_config`のworker URL・共有シークレットが必要。

- 既存の`0012_cron.sql`はDBに記録されたハッシュとリポジトリの内容が異なる。今回そのファイルと履歴は変更していない。通常の`db:push`は差異を報告して終了コード1になるが、新しい番号のマイグレーションは適用済み。

## 生徒の登録と初回ログイン

- 新規生徒はメールアドレス不要。ログインIDは所属ごとに `student1`、`student2`… とDBで自動採番する。登録画面でのID入力は不要。既存番号・同時登録・削除後の非再利用に対応し、既存ユーザーのIDは変えない。
- 初期パスワードはサーバーで自動生成。登録直後に所属コード・ログインID・初期パスワードを管理者へ表示する。この画面を離れると初期パスワードは再表示できないため、控えて本人へ渡す。
- 生徒は「所属コード＋ログインID＋初期パスワード」でログインし、12文字以上の別のパスワードへ変更する。変更前は学習画面・API・DBの所属データへのアクセスを制限する。
- 既存ユーザーに初回変更を一括要求しない。先生・管理者の登録では従来どおりメールアドレスとパスワードを指定する。
- ログイン画面の「所属コードをこのブラウザに保存する」を選ぶと、ログイン成功時に所属コードだけをlocalStorageへ保存する。チェックを外すと削除する。ID・パスワードはこの機能では保存しない。
- DBの既存名`school_codes`と旧APIパラメータ`schoolCode`は互換性のため維持し、画面と新API入力は「所属コード」／`organizationCode`とする。
- `SMOKE_AUTH_ONLY=1 npm run test:smoke`で実認証の一連の処理をAI呼び出しなしで確認できる。テスト用の学校・ユーザーは終了時に削除する。

## 登録済みユーザーの編集

管理者の「ユーザー管理」→対象ユーザーの「編集」で変更する。氏名・利用状態に加え、生徒はログインID・学年・利用目的・模試結果・苦手範囲・1日の学習時間を更新できる。模試結果はPDF・画像からの読み取りにも対応。
基本情報と学習プロフィールはまとめて保存し、エラー時に一部だけ変更しない。更新した情報は次回の学習計画・個別のお題生成に利用する。保存操作だけでは宿題の再生成・自動配信は行わない。

## 2026-09-21：模試の背景分析と全ロールの認証情報発行

- 登録時の必須項目は氏名・ロール。生徒は学年、先生・管理者はメールアドレスも必要。生徒のログインIDは自動発行。担当の先生とクラスは任意（後から設定可）。画面では赤い「必須」を表示する。
- 利用目的・目標、苦手範囲、模試結果、1日の学習時間は任意。未設定の学習時間はDBでもnull。計画生成の時間上限は未設定時に30分を内部の仮値として用いる。
- ファイル選択ボタンは緑。選択すると自動で分析を開始する。模試ではページごとにFlashで数値と表見出しを抽出し、検算と初期プロフィール提案はコードで行う。個別の学習計画生成は既存の後続ジョブで行う。
- 分析は`exam_analyses`と`analyze_exam`ジョブで保持する。アップロード完了後はブラウザを閉じてもサーバーで継続。PDF変換・アップロード自体が終わる前にブラウザを閉じた場合は再アップロードが必要。
- 分析を待たずに登録可能。登録とアップロードのどちらが先でも同じ分析IDへ結び付け、結果が届いたら保存済みプロフィールへ反映する。アップロード開始後の手入力変更、別の分析に切り替えた生徒情報を上書きしない。
- 初期の目標と時間は、検査した模試結果からコードで作る変更可能な提案であり、本人の希望や最適時間の断定ではない。個別学習計画は後続AIジョブで作る。判読できない値は推定せず、空欄と確認事項を返す。
- ユーザー管理下部の「模試の分析状況」で処理状況を確認できる。疑義のある結果は確認画面で元資料と照合・修正して承認するまで反映しない。失敗時は再アップロードか手入力で進められる。原画像は自動反映完了・失敗・確認後の承認時に削除する。
- 全ロールで初期パスワードをランダム生成。登録後のポップアップで所属コード・メールアドレス／ログインID・初期パスワードをコピーできる。パスワードは画面を閉じると再表示できず、ログへ保存しない。
- 管理者はユーザー編集画面の「初期パスワードを再発行」から所属内の全ロールをリセット可能。再発行後は本人による変更を必須にする。古いセッション・更新トークンとJWT世代も失効し、同時の変更操作は排他制御する。
- AI利用状況は利用者×機能×モデルで集計し、どの画面・処理で使用したかを表示。直近30件から実行詳細へ移動できる。
- DB変更：`0034_background_intake.sql`、`0035_password_reset_sessions.sql`。設定済みDBへ適用済み。
- 検証はAI予算0の一時所属と固定の分析結果を使用する。実モデルでのプロフィール提案品質はこの検証では測定していない。

検証記録：既存・追加テスト計142件（139件の全体実行＋背景workerの追加3件）、ESLint、TypeScript、本番ビルドを確認。AI予算0の一時所属で全ロールの再発行と再ログイン、Chromeで分析中の登録・離脱後反映・手入力保持・コピー・機能別表示を確認した。一時データは削除・ロールバック済み。

## 授業後の業務を中心にした変更（2026-09-21）

- `0036_lesson_preparation.sql` と `0037_preparation_recovery.sql` を適用。授業記録を共有保存し、在籍生徒ごとの独立したジョブを作成。最大100人、同じ受付IDの再送は重複生成しない。
- 資料の画像読み取りは一度行い、抽出テキストを生徒別の計画生成で共用。生徒ごとの課題・計画を同じモデル呼び出しで作成し、保存済みの計画からの再開ではモデルを再呼び出ししない。
- 一括確認・編集・配信はDBトランザクション。確認時の版番号と現在の版番号が違う場合や、担当外の課題が混在する場合は全件を取り消す。生徒へは公開済みの本人用課題だけを表示する。
- 既存の廃止済み承認キューテーブルは復活させず、課題の下書き→先生の承認・配信という導線に統一。
- 最新の授業範囲・クラスの科目・個別の対話と最終評価・前の計画を計画生成へ渡す。先生が修正した評価では旧AI分析を優先しない。計画に前の計画IDと根拠評価IDを記録。
- 計画詳細・授業記録は生徒に非公開。新規の計画は先生の担当クラスでも制限し、別クラスの同じ生徒を担当しているだけでは読めない。
- 対話で一度まとめ直すことと、観測できた説明の改善を簡易フィードバックに示すことをプロンプトへ追加。学習効果の実証を意味しない。
- 先生・生徒・管理者の画面内ガイドと [配布用の使い方ガイド](user-guide.md) を追加。

検証：24ファイル・156テスト、TypeScript、ESLint、webpack本番ビルドを確認。SQL権限・原子性の検証はトランザクション終了時にロールバック。実Supabase接続でのworker検証とブラウザ検証は、専用の一時所属・ユーザーを使用して終了時に削除した。ブラウザでは授業受付、画面離脱後の個別案表示、編集、一括承認、生徒別配信、承認前の非表示、計画理由、先生・生徒ガイドとスマートフォン幅を確認した。モデル出力はテストで置き換え、OrcaRouterの追加呼び出しを行っていない。実モデルの課題品質・説明改善の品質は今回追加測定していない。

## 個別指導と利用終了の管理

クラスは任意。生徒の登録・編集で担当の先生を指定し、「授業と宿題」では生徒を直接選べる。集合授業は従来のクラス指定を使う。個別指導の学習領域は内部で自動作成し、既存RLSの担当制限を引き継ぐ。既存生徒にも領域を用意するが、新たな担当権限は自動付与しない。

管理者は生徒の編集画面とクラス管理からアーカイブ・復元できる。完全削除はアーカイブ後に影響件数と名前入力で確認し、DBトランザクションで実行する。生徒削除は認証アカウントも削除、クラス削除では在籍者アカウントや別の学習領域は保持。実行中ジョブがある間は削除を拒否し、アーカイブ後の新規書き込み・ジョブ開始にもガードを設ける。監査と所属の費用集計は保持する。

今回の管理機能は `0038`〜`0041` を接続済みDBへ適用済み。全体テスト164件が通過し、その後に追加した共有教材の保護を含む管理機能テスト8件も通過。ESLint・本番ビルド・ブラウザでのクラスなし登録／担当反映／個別配信／アーカイブ／復元／完全削除／スマートフォン幅を確認した。検証では実AIを呼ばず、専用データだけを使用・削除した。

## 模試の検証・復旧とモデル選択（追加改善）

専用の `exam` モデル経路は `AI_EXAM_MODEL`（既定Gemini 2.5 Flash）を使用。1試行60秒、ページごとの保存済み進捗から再開し、通信失敗・不正なJSONは同じページを1回まで再試行する。未検証の別モデルで模試を補わない。予算・安全性による遮断は再試行しない。対話の時間制限・モデルは変更していない。

`0053_exam_review.sql` の確認待ち状態により、登録前後どちらに分析が終わっても未承認の結果はDBの反映関数を通らない。承認者・時刻・元の抽出・修正前の提案を保存する。

実測結果と限界は [模試解析の採用判断・実装記録](exam-reading-reliability.md) を参照。

## 対話の取り消し状態（2026-09-22）

- 自己紹介・通常の課題とも、開き直したときに保存済みの最後の1往復から取り消しボタンを復元する。終了済み・返信待ちには表示しない。
- `0054_persist_conversation_undo.sql` で、取り消した直後に残る最後の生徒メッセージIDを記録する。再読み込み・別タブからさらに古い往復を取り消す操作はDBでも拒否し、新しい送信は別のIDになるので再び取り消せる。接続先DBへ適用済み。別環境への反映時にもこのマイグレーションが必要。
- 関連テスト28件、TypeScript・ESLint・本番ビルドが成功。実際のチャット部品と固定API応答を使ったChrome検証で、両モードの再表示・取り消し・再送を確認。DB検証はロールバックし、有料AIは呼んでいない。
