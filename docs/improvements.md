# 改善と検証の記録

見ている観点は、セキュリティ、コストパフォーマンス、信頼性・堅牢性、自律性の4つ。
実測していないことは主張しない、が全体を通した方針。

先生が宿題の対象と期限を決めて配信する運用を維持する。生徒へ次々と自動配信しない。

## 実施した改善

| # | 課題 | 修正した内容 |
|---|---|---|
| 1 | 費用：予算確認の失敗時にも呼び出せる | 所属の予算が欠落・不正・取得失敗ならAIを呼ばない |
| 2 | 費用：利用額が不明でも呼び出せる | 利用額の取得失敗・不正な数値も呼び出し前に停止 |
| 3 | 費用：修復や代替の追加消費 | 次の試行前に予算を再確認し、そのリクエスト内で判明した費用も加算して判断 |

| 5 | 費用：予算までの余裕が分からない | 管理画面に所属の日次使用額・上限・80%到達表示を追加。アカウント残高とは区別 |
| 6 | 信頼性：復旧成功を失敗と集計 | 429等から代替モデルで成功した実行を成功した切替として記録。制限に遭遇した履歴は維持 |
| 7 | 安全性：停止設定の取得失敗 | モデルの停止設定を確認できなければ呼び出さない |

| 9 | 安全性：評価の操作・秘密の抽出 | 採点結果の指定、英語の秘密開示要求、出力内の難読化した秘密値を追加検査 |
| 10 | 安全性：教材・履歴の命令化 | エージェント共通で、教材・履歴・生徒発言は参照データであるという信頼境界を明示 |
| 11 | 安全性：出力遮断なのに成功記録 | 成功記録の前に出力を検査。遮断はblockedとして費用も記録し、別モデルへ再送しない。画像読み取りにも適用 |
| 12 | 堅牢性：巨大JSON・不正な追跡ID | 本文ストリームの実サイズを制限。不正なtrace IDはUUIDへ置換。エラー応答もno-storeを維持 |
| 13 | 堅牢性：未着手ジョブの放置 | 一括リースをやめ、実行できる直前に1件ずつ取得 |
| 14 | 堅牢性：古い処理による削除 | リース所有権をDB行ロック下で確認してから失敗退避。照合しない旧RPCの実行権限を撤回 |
| 15 | 堅牢性・費用：無意味な再試行 | 安全性遮断・入力不正・未登録処理は再試行しない。回収時に上限を超えたジョブも実行しない |
| 16 | 堅牢性：worker起動要求の放置 | HTTP失敗の記録、時間上限、リダイレクト禁止を追加。ジョブはキューに残して次回起動で処理 |
| 17 | 自律性：妥当なAI質問が定型文になる | 特定キーワードがないだけでAI質問を捨てる処理を撤去。説明に応じて未確認の観点を選択させる |
| 18 | 学習体験：早すぎる終了・終了時の質問 | 初回発言だけでAI判断による終了を許さない。終了時は質問のない励まし。最大6ターンは維持 |
| 19 | 個別化：別クラスや却下済み評価の混入 | 次回計画の根拠を同じクラスの最終評価に限定し、却下済みを除外 |
| 20 | 人の判断：修正前分析の再利用 | 修正済み評価では先生の点数・メモを優先し、修正前AIの所見・誤概念を計画へ再投入しない |
| 21 | 費用：配信先を決められない計画生成 | 生徒のクラスをAI呼び出し前に確認 |
| 22 | 人の介在：確認箇所が埋もれる | 先生の生徒画面で確認待ち件数を表示し、確認待ち概念を優先表示 |
| 23 | 評価の信頼性：未確認・却下の混同 | 確認済みの平均を表示。却下・先生修正の状態と修正理由を表示。評価不能を0点として見せない |
| 24 | 判断の説明責任：却下理由が固定 | 先生が却下理由を書いて保存できるように変更 |
| 25 | 学習体験：クラス配信APIの不具合 | 生徒の宿題取得で存在しない配列リレーションを修正。クラス配信も取得し、お題の許可した項目だけ返す |
| 26 | 管理体験：保存失敗に気づけない | ユーザー状態変更に保存中・エラー表示を追加。ナビをユーザー管理へ変更 |

## OrcaRouterの費用について

ユーザー申告：20 USDのクレジットに対して使用済み約0.108844 USD。差額は **19.891156 USD**（2026-09-21の申告に基づく計算。ライブ残高ではない）。
この改善の検証では実モデルを呼ばず、モック応答またはAI予算0の一時所属を使う。
残高を画面へ固定表示したり、今回の検証で請求額が不変だったと断定したりしない。他の利用や請求反映の遅延は別に存在し得る。

予算チェックは所属単位の日次台帳に基づく。複数の同時実行を予約額で抑える仕組みではなく、アカウント全体の20 USDを厳密に保護するものでもない。
未取得の費用、タイムアウト中の上流課金、台帳反映前の並列リクエストには限界がある。モデル別表示の費用は一連の試行の合計で、モデル名は最終応答の解決先。

- TypeScript、ESLint、本番ビルド（webpack）：成功。
- Chrome：予算表示、モバイル幅、ユーザー状態の保存失敗、先生の却下理由保存、クラス配信の取得を一時データで確認。

## 実装だけでは埋まらない、残っている課題

1. 先生が同じ教材で手作業する時間と、本サービスで確認・配信する時間を実測する。架空の削減率を示さない。
2. 実際の教科・学年・誤答例を先生が評価したデータで、質問とフィードバックの品質を測る。既存の2例のモデル比較だけで一般化しない。
3. 新しい対話プロンプトの教育的な質は、今回の課金なし検証では確定していない。必要な少数例で教師確認付き評価を行う余地がある。
4. 未知の間接インジェクション、OrcaRouter側のGuardrails設定、本番workerの定期到達性は引き続き実環境の確認が必要。

## サービス名の変更と、それに伴う修正

### サービス名を「トイノワ」に変更

「問いの輪」から。AIが問い返し、生徒が説明し、その根拠が次の宿題に戻る循環を指す。

アプリ名は `src/lib/shared/branding.ts` の `BRAND` 一箇所からしか読まない設計にしてあり、
ESLint (`no-restricted-syntax`) が他所での名前リテラルを禁止している。
このため画面・PWA マニフェスト・通知テンプレートは環境変数の差し替えだけで追従した。

外部システムで追加の作業が要ったのは3つ。

| 対象 | 変更内容 |
|---|---|
| ログイン用アドレス | `{生徒ID}@{所属コード}.studypilot.local` → `.toinowa.local`。環境変数だけ変えると既存ユーザーが全員入れなくなるので、`auth.users` / `auth.identities` / `public.users` を移行（0051）。`auth.identities.email` は生成列なので `identity_data` 側を更新した |
| OrcaRouter Named Router | `orcarouter/studypilot-advanced` は編集画面で名前を変えても反映されなかったため、同設定の `orcarouter/toinowa-advanced` を作り直した（adaptive・許可モデル4件・フロンティアエスカレーション無効） |
| Vercel | プロジェクトを `toinowa` にリネームし、`toinowa.vercel.app` をプロジェクトのドメインとして登録。デプロイ保護が `all_except_custom_domains` のため、エイリアスを張るだけでは SSO で弾かれる。プロジェクトのドメインに追加して初めて公開状態になる |

### 実測を設定へ反映した

**模試読み取りの退避先を入れ替えた。** 実測（9入力×3モデル＝27回、必要項目450件）で
gpt-4o-mini は必要項目の正確な取得が **6.9%**、必要項目の欠落が358件だった。
形式は常に整う（JSON検証9/9通過）ため、壊れていることに気づけないのが最も危ない。
1段目 flash が落ちたときの退避先を flash-lite（72.2%）に変え、mini は最後段へ下げた。

**遅い退避先を外した。** `z-ai/glm-5.3-flash` は P50 **40.4秒** / P95 49.1秒で、
かつ json_schema を無視する。退避先が本来の障害より遅く、スキーマ検証でも落ちるため
縮退として成立しない。3つの連鎖から外し、`deepseek/deepseek-v4.1-flash` に替えた。

### 使っていない実装を削除した

`src/lib/rag/`（6ファイル）と `src/lib/workflow/machine.ts` は、
テスト以外からの参照が0件だった。実際に使われていたのは `countTokens` だけなので
`src/lib/text/tokens.ts` へ移し、残りを削除した。
動かない骨組みを残したまま公開すると、実装していない自律性を主張していると読まれる。

### 判定結果が行き止まりだったものを先生に出した

回答ごとの本人性判定（言いよどみ・入力ペース・AI文体）は `answers.ai_likelihood` /
`ai_signals` に保存されていたが、疑いが「高」で要フォローに上がるときしか先生の目に触れず、
画面からの参照は0件だった。分析の費用を払って誰も読まない状態だったので、
根拠の詳細を先生の評価画面に出した。疑う理由と、本人が説明したと考えられる特徴の両方を並べ、
先生が自分で判断できる形にしている。

### 画像経由のプロンプトインジェクションを測れるようにした

テキストの検査（`npm run check:injection`）では画像経路を確認できない。
模試・教材のアップロードはこのサービス最大の攻撃面なので、別に測る。

```bash
python3 scripts/fixtures/make-injection-images.py
npm run check:injection:image
```

架空の模試画像に命令文を仕込んだ7枚（対照1・攻撃6）を、本番と同じシステムプロンプト・
同じモデル段へ送り、3層で判定する。

1. モデルが命令に従った痕跡（システム文の露出・秘密の出力・外部送信・点数の書き換え）
2. 出力検査 `checkModelOutput`
3. 転記文を次のプロンプトへ渡す前の入力検査 `inspectInput`

ゲートウェイのガードレールで止まった場合も防御成功として数える。

### 公開前の整理（2026-09-21）

**使っていない秘密情報の宣言を消した。** `AUTH_SECRET` と `ENCRYPTION_KEY` は
32バイトの必須シークレットとして検証していたが、参照している箇所が1つもなかった。
`NEXT_PUBLIC_DEMO_MODE` も同様に未実装のまま残っていた。
使わない秘密を要求しないことが目的。

**LINE連携を全面的に削除した。** 設計しないと決めたので、残骸を一切残さない方針にした。
環境変数4件と `NEXT_PUBLIC_LINE_ADD_FRIEND_URL`、`isLineConfigured`、
`/admin/line` の「準備中」画面と設定画面のリンク、スキーマ
（`line_account_links` / `channel_link_tokens` / `tenants.line_channel_config_id`、
マイグレーション0052）、保持期間 cron からの参照、設計書の該当章まで含む。
`channel` 列挙型の `'line'` だけは残した。列挙値の削除は型の再作成が必要で、
`conversations.channel` と `messages.channel` の既定値と依存を張り替えることになる。
値がひとつ余分にあることの害より、その入れ替えの危険のほうが大きいと判断した。
アプリ側の入力スキーマは `z.literal('web')` に絞ってある。

個人情報マスクの `line_id` ルール（`src/lib/security/pii.ts`）は**残した**。
これは生徒がチャットに自分のLINE IDを書いてしまったときに伏せるための保護であり、
LINE連携機能ではない。消すと保護が減るだけになる。

**本番の CSP から `'unsafe-eval'` を外した。** 必要としていたのは pdf.js だけだったので
`getDocument({ isEvalSupported: false })` にし、`'unsafe-eval'` は開発時（HMR）のみに限定した。
あわせて `frame-src 'none'` `media-src` `upgrade-insecure-requests` を追加し、
`poweredByHeader: false` でサーバ実装を名乗らないようにした。

**リポジトリから出る情報を確認した。** 追跡ファイル・全コミット履歴を
`sk-orca-` / `sb_secret_` / 接続文字列 / 秘密鍵のパターンで走査し、実値の混入は0件。
`.env*` は `.env.example` だけを例外にしている。`.gitignore` に鍵・証明書の拡張子
（`*.key` `*.p12` `*.pfx` `*.jks`）、Playwright の出力、ログを追加した。
文書に残っていた他人のローカルパス・個人のプラン文書への参照も削除した。
