# 展示・発表・記事に使う根拠一覧

更新：2026-09-21。目的は、ファインマンテクニックに着想を得たStudyPilotで「教える先生」と「説明を聞き、復習・定着・計画作成を支えるAI」の役割分担を示し、ハッカソンの「業務の自律化」を具体的に伝えること。

提出期限・必要項目・展示全体の準備は [発表準備メモ](hackathon-presentation-brief.md) を参照。9月22日15時までの事前提出物で決勝進出が審査される。OrcaRouter賞はユーザー訂正に従い5万円。

## 模試読取について、そのまま使える短い説明

> 先生が課題や評価基準を一から設計する負担を減らすため、授業記録や模試の情報からAIが準備を進めます。模試の読み取りではOrcaReplayで同じ入力を比較し、モデルの価格だけでなく、必要項目の取得、待ち時間、失敗、確認負担を測りました。上位モデルも試しましたが、今回の条件ではFlashより品質上の利点が確認できず、費用と時間が増えたためFlashを採用しています。疑わしい結果は勝手に計画へ流さず、人が原資料と照合して承認します。

## 評価項目ごとの主張と根拠

| 評価項目 | 今回説明できること | 根拠 | 説明の限界 |
| --- | --- | --- | --- |
| コストパフォーマンス | 上位モデルへ変える前に処理を改善し、同じ条件で費用・時間・取得内容を比較して採用判断した | 下のA/B比較表、v1〜v3報告、OrcaReplay記録 | Flashがすべての文書で最適とは言わない |
| 信頼性・堅牢性 | 成功したページを保存し、失敗したページだけ1回再試行。検証できない結果は自動反映を止める | worker・DB・承認APIのテスト、実ブラウザ試験 | プロバイダー全体の障害に対する別社への切替試験は未実施 |
| 自律性・人の介在 | AIが抽出、コードが検算・初期提案、疑義のある時だけ管理者が照合。個別計画と課題案は既存フローで作り、先生が確認して配信 | 確認画面、未承認結果のDB反映拒否、既存授業準備フロー | 模試の表見出し不足で人の確認が必要な例も正直に示す |
| セキュリティ | 管理者・所属・アップロードした本人を確認。生徒から原資料を読めない。資料内指示を命令として扱わないプロンプトと既存ガードを使用 | RLS/権限試験、承認API、原画像削除確認 | 攻撃入り模試画像での耐性実測は今回していない |
| アイデア・独創性 | 模試の転記だけでなく、生徒が自分の言葉で説明する対話・理解度把握・復習計画へつなげる | サービスの授業→説明対話→フィードバック→計画更新のデモ | 成績向上・学習効果の実証済みとは言わない |

## 展示で載せる比較表

同一のスキャン画像・要求形式、各モデル各資料1回、60秒期限。2資料だけの診断的な比較。

| 資料 | Flash | 2.5 Pro |
| --- | --- | --- |
| 模試A | 必要57項目一致／28.56秒／$0.016112 | 必要57項目一致／54.80秒／$0.110792 |
| 模試B | 必要30項目一致／15.98秒／$0.009134 | 60秒でタイムアウト／費用未確定 |

**読み取る品質が同じだったAで、Proは約6.9倍の費用・約1.9倍の時間。今回はFlashを採用。** Bのタイムアウトを誤読率と混同しない。

補足のC資料はFlashが63項目一致したが、表見出し不足で確認待ちになった。「数値を読めた」と「無確認で自動反映してよい」を区別する例として説明する。

全試験の確認済み費用は累計$0.470756。未確定5件の留保を含む予算管理額は$1.720756、承認上限は$2。いずれも未確定分を含む実請求総額とは異なる。

## 60〜90秒のデモで見せる場面

1. **15秒：業務の入口。** 授業記録を渡し、生徒別の課題案が準備される流れを見せる。先生が問題文を全員分作る必要がないことを説明する。
2. **20秒：生徒の体験。** 生徒がAIへ説明し、問い返しで考え直す場面を見せる。実在生徒の対話は使わず、デモ用のアカウント・文章にする。
3. **20秒：判断の根拠。** 模試モデルの比較表を示す。「上位モデルが常に得とは限らず、実測で選んだ」と説明する。
4. **20秒：人が確認する地点。** 疑義のある模試について、元資料・読み取り候補・確認理由が並ぶ画面を示す。承認までは反映されず、必要箇所を直してから反映する。
5. **15秒：計画と宿題。** 個別計画・課題案を先生が確認して配信する画面で締める。学習効果を実証したという主張はしない。

既存機能を含むデモ順なので、発表前に本番のデモアカウントで通し確認する。模試のライブ解析に全時間を使わず、待ち時間のある箇所は事前に準備した結果や動画で示す。

## 誇張を避けるための表現

| 使える表現 | 避ける表現 |
| --- | --- |
| 今回の資料・設定で必要項目が一致した | OCR精度100%、どんな模試でも正確 |
| 初回の失敗と再試行の結果を別に記録した | v1の88.7%から99.6%へ改善した、と条件を省く |
| コードは抽出された見出しと数値の整合性を検査する | コードが元画像の意味を完全に理解し誤読を防ぐ |
| 元資料との照合が必要な時は人に戻す | 完全自動で人の確認は一切不要 |
| 初期の目標・時間は変更可能な提案 | 生徒に最適な学習時間が実証された |
| 復旧できなければ失敗を明示して手入力へ進める | AIが停止してもすべての機能が継続する |
