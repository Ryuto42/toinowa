# StudyPilot：提出記事・展示資料の構成案

2026-09-21。主催者の追加案内を踏まえた提案。記事・ポスター・動画はまだ公開／制作完了していない。事前課題による決勝選考と9月22日15時の締切を優先する。

## 共通して伝えること

見出し案：**先生は授業に集中。AIが、一人ひとりの復習を設計。**

説明案：StudyPilotは、授業記録・教材・模試結果から個別の説明課題を提案するサービスです。先生が確認して配信し、生徒がAIに自分の言葉で説明。対話から理解の手がかりを集め、次の復習・学習計画へつなげます。ファインマンテクニックに着想を得て、先生の宿題準備・理解度確認・次回指導の準備を支えます。

先生が教える → 授業記録を渡す → AIが生徒別に課題を設計 → 先生が確認・承認 → 生徒がAIへ説明 → AIが根拠付きの振り返りと次回案を作る。

図では「先生」「AI」「生徒」の担当を明示する。アウトプット学習を実際に行うのは生徒。AIは設計・対話支援・分析を担当し、配信判断は先生に残る。理解度を完全に測定できる、学習効果や業務削減率を実証した、とは書かない。

## 提出記事の骨子

1. 先生が授業後に抱える仕事：宿題設計、生徒ごとの理解の確認、次回計画。
2. StudyPilotの体験：役割別の図と短いデモ。個別指導にも使う想定を示す。
3. AIが判断する部分と、先生が確認・承認する部分。単なる生成と固定処理を区別する。
4. 5評価項目の証拠。最新の実装と検証記録に照らして主張を確認する。
5. OrcaRouterをどこで使ったか。用途別モデル、利用記録、OrcaReplayでの比較。使っていない機能も全部使ったように書かない。
6. 実測で見つかった問題と改善。改善後の未測定の数値を埋めない。
7. 制約、今後の検証、ソースコード・起動方法。
8. OrcaRouter https://www.orcarouter.ai/ja とAI HACK https://aihackathon.jp/ への言及・リンク。

フォームに必要なチーム番号・提出用メール、記事公開先、提出対象のソースの版は提出準備時に確認する。フォームの最終送信と外部公開はユーザーからの指示に従う。

## ポスターの文章たたき台

**StudyPilot**

**先生は授業に集中。AIが、一人ひとりの復習を設計。**

授業記録から課題を作り、生徒の「説明」から次の学びへ。

- 先生：授業記録・資料を渡し、AIの課題案を確認して配信。
- 生徒：AIに自分の言葉で説明し、理解を深める練習。
- AI：授業・模試・対話の情報から、個別の課題と次回計画を提案。

中央に上記の役割別フロー。下部に先生の承認画面と、生徒の説明対話画面を大きく配置する。画面と文言は最新版の動作を確認してから採用する。

小さな根拠欄：**品質・費用・失敗を実測して設計を検証。**

QRの行き先は公開記事またはデモ紹介ページ。実験用APIキーや管理者ログイン情報を載せない。サービスの価値を主役にし、長いモデル比較表は補助資料へ置く。

## ベンチマークの見せ方

現時点の資料は [模試モデル比較結果](exam-model-benchmark-results.md)。2回分・3ページ・9入力条件という範囲を示し、「88.7%」だけを大きく掲示しない。必要項目の取得率、JSON失敗、平均点と割合の混同を分ける。

改善試験を行った場合は、同一条件の改善前後、再試行込みの確認済み費用、未確定費用、先生の確認が必要な箇所を併記する。「改善前後を測った」という説明ができる1サイクルを優先する。計画の妥当性や学習効果を、読み取り精度だけで実証したと表現しない。

## 審査員への説明の長さ

- 10秒：誰のどの仕事を任せるか。見出しと役割別フロー。
- 60〜90秒：一人の生徒の課題作成から、対話・次回案まで。
- 詳細質問：5基準の補助資料と記事で、実測・障害時・承認の根拠を示す。

自律化の業務の流れを見せた後に、モデル選定・コスト・安全性の設計を説明する。最初から技術名と検証指標を列挙しない。
